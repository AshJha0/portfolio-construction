portfolio-construction

A four-language reference implementation (Python reference, C++, Rust, Java) of classical portfolio construction: sample and Ledoit-Wolf shrinkage estimators, closed-form and box-constrained Markowitz mean-variance optimisation via a finite dual active-set QP, Black-Litterman posterior blending, risk parity and risk budgeting by cyclical coordinate descent, and a quarterly expanding-window backtest on a bundled 8-asset, 1250-day universe. Every numerical algorithm is pinned in API_SPEC.md — Cholesky variant, simplex-projection breakpoint scan, the QP and its KKT certificate, the CCD update, Ledoit-Wolf sums term by term — so the scipy/LAPACK-free ports agree with the Python reference on 23 golden cases.

What the latest review found and fixed. Two correctness defects in the original design. First, the Ledoit-Wolf constant-correlation intensity kept a weight of rbar/2 on theta_ii,ij per ordered pair, halving the paper's correction and over-shrinking by 31 % on the bundled data (0.00943 instead of 0.00721); the sums now follow Ledoit & Wolf (2004) Appendix B / covCor.m term by term and the suites check them against a direct transcription. Second, the constrained frontier was solved by projected gradient descent on a quadratic penalty whose Hessian condition number was ≈ 7e5: a 10,000-iteration cap silently returned a point 1.7e-3 from the minimiser and a step-size stopping rule certified nothing. It was replaced with a finite Goldfarb-Idnani dual active-set QP that meets the target-return equality exactly and returns a KKT certificate; weights-only wrappers now raise rather than return an uncertified point. golden.json was regenerated (23 cases, validated against SLSQP and covCor.m) and all three ports re-pinned. This is a verified reference implementation of the published algorithms, not a production portfolio system.

What's inside

Estimators

sample_mean / sample_cov (mean divisor T, covariance ddof = 1, correctly rounded sums), shrink_covariance with the Ledoit-Wolf (2004) constant-correlation target and intensity exactly per Appendix B / covCor.m, applied in the ddof = 1 convention, and annualize_mean / annualize_cov multiplying by a validated periods (252 by default).

Pinned linear algebra

cholesky, chol_solve, spd_solve, spd_inverse: Cholesky-Banachiewicz with a relative pivot gate of 1e-13; every inverse is a pair of triangular solves. Singular covariance (a duplicated asset) is caught by the pivot, and the ports carry no BLAS/LAPACK dependency — the same arithmetic runs in all four languages.

Markowitz: closed forms and QP

Two-fund A/B/C/D scalars, min_variance_weights, tangency_weights with a conditioning guard (TangencyUndefinedError), gross_leverage and a 25-point efficient_frontier. Box-constrained problems use an exact sort-based simplex projection (Duchi 2008 / Kiwiel 2008) for feasibility and a Goldfarb-Idnani dual active-set QP with KKT certificate for min_variance_longonly and constrained_frontier; unattainable targets are rejected with the attainable range in the message.

Black-Litterman

implied_equilibrium_returns (reverse optimisation, pi = delta Sigma w_mkt), views_to_matrices for validated absolute and relative views, He-Litterman default_omega = diag(P tau Sigma P') scaled by per-view confidence, and a posterior computed through one k×k Cholesky solve. Works in excess-return space, so its tangency is pinned at rf = 0; Idzorek confidence calibration is explicitly not implemented.

Risk parity & budgeting

risk_contributions, erc_weights, risk_budget_solve / risk_budget_weights and inverse_vol_weights. The solver is cyclical coordinate descent on Spinu's (2013) log-barrier formulation with the positive-root update, tol 1e-10 and a 10,000-sweep cap reported via a flag; the result is scale-invariant and permutation-equivariant, and the demo's ERC risk-contribution spread is 1.30e-12.

Backtest-lite

rebalance_indices, run_backtest and the metrics annualized_return, annualized_vol, sharpe_ratio, max_drawdown: an expanding window of 500 rows re-estimated every 63 rows with L1 turnover between target vectors. Index-based (rows are trading days), no transaction-cost model — turnover is reported, never charged — and no missing-data handling; T ≥ window + 2, r > −1 and finite rf are validated.

Golden suite & testing

data/golden/golden.json holds 23 cases with a flat schema (vectors as w_0..w_7, matrices as cov_i_j), produced by the Python reference on the CSV as parsed (doubles round-trip via %.17g). Every golden quantity is a closed form or the exact solution of a finite algorithm, so agreement is a rounding question, not an iteration-path question; the Rust suite adds 33 property tests, and the QP is checked against SLSQP, brute-force enumeration and ~1500 random problems.

Units, validation, scope

Daily simple returns as decimals, weights summing to 1 (negative = short), annual-decimal rf. Validated everywhere: NaN/inf, returns ≤ −1, shape mismatches, non-SPD covariance, infeasible bounds, malformed views, tau outside (0, 1], delta ≤ 0. Respect n ≤ ~20 assets (dense O(n³)) and check gross_leverage on unconstrained weights. Out of scope: calendars, transaction costs, leverage/turnover constraints inside the optimiser, condition-number diagnostics beyond the pivot gate, multi-period objectives.

Quick start

git clone https://github.com/AshJha0/portfolio-construction && cd portfolio-construction

# Python (3.11 + numpy; pytest and scipy for the tests only)
cd python
PYTHONPATH=src python3 demo.py           # end-to-end demo (~0.3 s)
PYTHONPATH=src python3 -m pytest -q      # 114 tests incl. the golden suite (~1 s)
cd ..

# C++ (C++17, CMake >= 3.16, GoogleTest)
cd cpp
bash build.sh                            # cmake -S . -B build -DCMAKE_BUILD_TYPE=Release && cmake --build build -j2
./build/portopt_demo                     # demo (data resolved at ../data)
ctest --test-dir build --output-on-failure   # 90 tests
cd ..

# Rust (edition 2021)
cd rust
cargo build --release                    # zero warnings
cargo run --release --bin demo
cargo test --release                     # 58 tests (23 unit + 2 golden + 33 property)
cd ..

# Java (21, JUnit 4 + Hamcrest — no Maven/Gradle)
cd java
bash build.sh    # javac -Xlint:all -Werror everything into out/
bash demo.sh     # runs the demo main
bash test.sh     # JUnitCore on all *Test classes: 108 tests

# regenerate the dataset and golden values
python3 data/generate_data.py
