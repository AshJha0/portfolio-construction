portfolio-construction

Portfolio construction answers one question: given a set of assets, how much of each should we hold? This project implements the classical answers (mean-variance optimisation, Black-Litterman and risk parity) four times, as a Python reference and ports in C++26, Rust and Java 25.

Every algorithm is pinned step by step in API_SPEC.md, and all four test suites check the same 26 golden cases in data/golden/golden.json. The ports call no numerical library, so the same arithmetic runs in every language. Version 1.3.0.

The bundled data is synthetic. data/asset_returns.csv is simulated by data/generate_data.py: 8 assets named after asset classes, 1250 daily returns from a three-factor model (global equity, rates, carry) with Gaussian factors plus Student-t noise (6 degrees of freedom), constant drifts, numpy.random.default_rng(42). Market caps are fixed numbers for the whole sample. Nothing on this page is market data, and the demo backtest shows the code paths working, not the performance of any strategy. For scale: EM_EQ is generated with a 9.0% annual drift and its sample mean over the 1250 days is 2.9%.

What's inside

Estimators

sample_mean and sample_cov (divisors T and T-1, correctly rounded sums), shrink_covariance with the Ledoit-Wolf (2004) constant-correlation target and intensity per Appendix B and covCor.m, and annualize_mean / annualize_cov with a validated periods (252 by default).

Pinned linear algebra

cholesky, chol_solve, spd_solve, spd_inverse: Cholesky-Banachiewicz with a relative pivot gate of 1e-13; every inverse is a pair of triangular solves. A singular covariance (for example a duplicated asset) is rejected by the pivot gate, not repaired.

Markowitz

Two-fund A, B, C, D scalars, min_variance_weights, tangency_weights (raises TangencyUndefinedError at or above the minimum-variance return, or above 10x gross leverage), gross_leverage and a 25-point efficient_frontier. Box-constrained problems use a sort-based simplex projection (Duchi 2008, Kiwiel 2008) and a Goldfarb-Idnani dual active-set QP for min_variance_longonly and constrained_frontier. min_variance_turnover and mean_variance_turnover add a turnover penalty kappa * sum|w - w0| and an optional turnover cap, solved exactly through the buy/sell split w = w0 + b - s with a KKT certificate.

Black-Litterman

implied_equilibrium_returns (pi = delta Sigma w_mkt), views_to_matrices for absolute and relative views, He-Litterman default_omega = diag(P tau Sigma P') scaled by per-view confidence, and a posterior through one k-by-k Cholesky solve. Works in excess returns, so bl_weights uses rf = 0 by default. Idzorek's confidence calibration is not implemented.

Risk parity and budgeting

risk_contributions, erc_weights, risk_budget_solve, risk_budget_weights, inverse_vol_weights. Cyclical coordinate descent on Spinu's (2013) log-barrier form, tol 1e-10, at most 10,000 sweeps. risk_budget_solve reports convergence; the weights-only wrappers do not.

Backtest-lite

run_backtest re-estimates the target every 63 rows on an expanding window starting at 500 rows and holds that target exactly on every day in between: a daily-rebalanced constant mix. Turnover is L1 between consecutive targets; drift is not counted and no costs are charged. Metrics: annualized_return, annualized_vol, sharpe_ratio, max_drawdown.

Scope

Daily simple returns as decimals; weights sum to 1 (negative = short); annual-decimal rf. Sized for up to about 20 assets (dense O(n^3) algebra). Out of scope in the pinned core: calendars, transaction costs in the backtest, covariance repair, multi-period objectives. The Python research layer adds return signals (momentum, reversal, low risk), costs, drift, EWMA and nonlinear shrinkage estimators, volatility targeting and walk-forward evaluation on real data.

LEARN.md covers mean-variance foundations, estimation error, Ledoit-Wolf with a worked intensity, why long-only constraints regularise, Black-Litterman, risk parity, a desk workflow, where portfolio-construction P&L comes from, and a knowledge-check Q&A. Results

Synthetic study144 configurations on the bundled data; no difference between rules is statistically meaningful (largest DSR 0.58). Checks the instruments, not any rule. cost_aware_allocation.md
Real data, development 1926-201510 and 49 Kenneth French industries, monthly, 10 bp assumed. 1/N net Sharpe 0.47 on 10 industries; volatility targeting +0.13 (p = 0.02, mostly 1928-1969); min variance +0.15 on 49 industries (p = 0.15); uncapped tangency lost all capital in 1929. real_data_study_dev.md
Pre-registered holdout 2016-01 to 2026-09A negative result. None of six hypotheses supported; every Holm p-value 1.00; all six differences have the wrong sign (volatility-targeted 1/N -0.19, min variance on 49 industries -0.15, capped tangency -0.40). The market (0.73) beat 1/N (0.67, 0.64). Power was 0.04 to 0.28, so this does not show the levers are worthless, only that their development gains were too small and regime-dependent to rely on. real_data_study.md
SignalsHistorical evidence for momentum before 2016 only, no edge established after costs and correction, being tracked forward. The library has 12-1 and time-series momentum, short-term reversal, low volatility, low beta, a combiner, IC*sigma*z alphas, Black-Litterman views, rank portfolios and turnover-QP sizing. None of four registered hypotheses supported (Holm p 0.77 to 0.92); momentum +0.10 to +0.11 over 1/N in development, small and within one SE in 2016-2026, below the market; low vol reversed; short-term reversal lost about 0.3. 2016-2026 was a seen period, and the registration was recorded locally before the run but not pushed first. signal_study.md
BenchmarksLong-only QP at n = 8: about 8 us in C++, Rust and Java, 460 us in Python; one non-idle laptop, gaps under 2x not meaningful. benchmarks.md

Quick start

git clone https://github.com/AshJha0/portfolio-construction
cd portfolio-construction

# Python 3.11 or later
python -m pip install -e "python[dev]"
pytest -q python
python python/demo.py

# C++26, CMake 3.25 or later (GoogleTest fetched if not installed)
cmake -S cpp -B cpp/build -DCMAKE_BUILD_TYPE=Release
cmake --build cpp/build --config Release --parallel
ctest --test-dir cpp/build -C Release --output-on-failure
(cd cpp && ./build/portopt_demo)     # Windows: build\Release\portopt_demo.exe

# Rust stable
(cd rust && cargo test --release && cargo run --release --bin demo)

# Java 25 with Maven
(cd java && mvn -B verify && mvn -B -q exec:java)

# figures (adds matplotlib) and data regeneration
python -m pip install -e "python[docs]"
python docs/make_figures.py
python data/generate_data.py
